# 운영 기록 (2026-09-18 ~ 11-07)

Paddock의 원본은 약 30명 규모의 친구 커뮤니티에서 약 2개월 동안 실제로 운영했다. 그중 7주 동안 라이브 DB를 내리지 않고 60건의 패치 스크립트를 적용했다. 이 문서는 그 가운데 게임 규칙·보안·정산·관리 도구와 관련된 14건을 골라 정리한 것이다. 원본 스크립트는 공개하지 않는다.

## 그때의 패치 방식과 한계

원본은 번호가 붙은 SQL 파일 25개를 순서대로 실행하는 구조였다. 라이브 DB에는 전체 파일을 다시 돌릴 수 없었다. 그래서 고칠 함수의 몸통을 번호 파일에서 복사해 날짜가 붙은 패치 파일로 만들어 실행했다. 이 방식에는 약점이 있었다.

- **같은 함수가 여러 곳에 생긴다.** 패치 파일마다 함수 사본이 남는다. 오래된 패치를 다시 실행하면 그 뒤에 들어간 변경이 조용히 사라진다. 그래서 여러 패치 파일의 머리에 "이 파일은 낡았다. 돌리지 말 것"이라는 경고를 직접 달아야 했다.
- **9월 18일 사고가 이 위험이 실제로 터진 경우다.** 아래 표의 첫 줄을 보라.

이 경험 때문에 공개판은 Supabase CLI 마이그레이션 구조로 옮겼다. 함수 몸통은 마이그레이션 한 파일에만 두고, 라이브 변경은 새 마이그레이션 파일로만 추가한다. 자세한 내용은 [케이스 스터디 4](case-studies/04-ops-incident-and-migrations.md)에 있다.

## 키노 환수율

| 단계 | 변경 | RTP |
| --- | --- | --- |
| 09-28 | 배당 ×1.5/×4/×15/×50 → ×3/×15/×30/×60. 확률은 그대로 둠 | 0.883 → 약 2.32 |
| 09-28 | 가장 흔한 2개 적중(.278)만 ×1.5로 되돌림 | 약 1.90 |
| 10-02 | 4개 적중 빈도 1/104 → 1/4,630 (재추첨으로 보정) | 약 1.635 |
| 10-06 | 3개 적중 빈도 1/12.5 → 1/15 | 약 1.44 |
| 10-07 | 3개 적중 빈도 1/15 → 1/28.5. 배당표는 그대로 | **약 0.98** |

마지막 단계에서 키노의 하우스 엣지를 룰렛 2.00%, 슬롯 1.91%, 하이로우 2.04%와 같은 수준으로 맞췄다. 배당표를 다시 고치지 않고 재추첨 확률 하나만 바꿨기 때문에 4·5개 적중 빈도는 그대로 유지됐다. 지금은 이 값들을 서버 `get_rules()`가 내려준다. pgTAP은 서버 규칙 함수로 RTP 0.98과 3개 적중 1/28.5를, Vitest는 같은 값으로 룰렛·슬롯·하이로우 기대값을 검증한다.

돌아보면 첫 단계에서 "배당만 올리고 확률은 그대로 둔다"고 정한 결정을 수치로 먼저 확인했어야 했다. 이후 네 번의 수정은 모두 그 결정을 되돌리는 작업이었다. 그래서 공개판에서는 배당과 확률을 바꾸면 테스트가 바로 실패하도록 만들었다.
